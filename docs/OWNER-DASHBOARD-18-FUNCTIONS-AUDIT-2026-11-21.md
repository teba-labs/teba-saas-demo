## 4. قرار الواجهة المتفق عليه
- شاشة Dashboard الرئيسية تعرض **18 زرًا فقط**، لا أقسامًا مفرودة أسفل بعضها.
- كل زر يفتح مساحة مستقلة بمحتوى هذا التقرير وفلاتره وجداوله ورسومه وأدواته.
- زر رجوع ثابت وواضح يعيد المستخدم إلى قائمة الـ18.
- كل هذه الشاشات خاصة بمالك المعمل؛ لا تعرض للموظف بيانات مالية أو ربحية شاملة.
- لا نضيف زرًا رقم 19. المطابقة الشهرية تظل مستقلة عن مقارنة الأداء الشهرية؛ المقارنة الزمنية تكون ضمن التقرير الشهري/السنوي ولا تستبدل المطابقة.
- الأولوية البصرية للوظائف التشغيلية اليومية، ثم المقارنات والتقارير، ثم تحليلات المحفظة التاريخية.
- كل شاشة تعرض مصدر البيانات بوضوح: تشغيل حي، أو Excel تاريخي محلي، أو مقارنة بينهما.
- لا تُحسب «الأرباح» من صافي التحصيل ناقص المصروفات النقدية فقط؛ ذلك صافي حركة نقدية وليس ربحًا محاسبيًا.

## 5. مخاطر يجب إغلاقها قبل اعتماد التطوير
1. **مصدر الإيراد:** المطابقة تقارن تحصيل دفتر الحركة الحي بإيراد Excel التاريخي؛ المؤشران ليسا متطابقين بالتعريف.
2. **الربحية:** ربح التحليل التاريخي يعتمد على ملفات أسعار/تكلفة وتخصيص مصروفات؛ لا يجوز إسقاطه على الأداء الحي بلا نموذج تكلفة موثوق.
3. **النسخ:** أرشيف Excel في IndexedDB محلي فقط، وليس نسخة سحابية ولا يظهر على جهاز آخر.
4. **Live:** حالة التحاليل المعلقة/المنشورة اليومية لكل فرع في الشاشة القديمة ليست موجودة ضمن شاشة SaaS الحالية التي تمت مراجعتها.
5. **إدخال الحركات:** يبقى الإدخال في Workday لتجنب الازدواجية؛ Dashboard للمالك تعرض وتراجع ولا تنشئ نفس الحركة مرة أخرى.
6. **التزامن:** فرع العمل الحالي لقطة مستقلة. يجب مقارنة تغييرات صفحة النتائج المتزامنة قبل أي دمج إلى فرع التطوير.
7. **الاختبارات:** الاختبارات الوحدوية/الثابتة لا تثبت تجربة متصفح حية، ولا تثبت بيانات إنتاج أو Cloud backup.

## 6. خطة التنفيذ المعزولة
1. إكمال جرد DOM والأحداث والبيانات لكل قسم قديم وربطه بوحدات SaaS المقابلة، مع حفظ الوظائف غير المنقولة كفجوات صريحة.
2. بناء غلاف تنقل للمالك: شاشة رئيسية بـ18 زرًا وشاشات منفصلة ورجوع واضح، مع المحافظة على الدخول والصلاحيات والفلاتر المشتركة.
3. تقسيم محتوى التقارير الحالية والتاريخية إلى شاشات مستقلة دون نسخ مصادر البيانات أو تكرار استعلاماتها.
4. استكمال الوظائف الحية الناقصة أو عرضها بوضوح كغير متاحة بدل بيانات وهمية؛ خصوصًا Live وحركة اليوم وسجل الحركات.
5. استكمال شاشات التقارير التاريخية اعتمادًا على المحركات الموجودة، مع وسم مصدر Excel والتكلفة وحدود التغطية.
6. مراجعة صلاحيات المالك/الموظف، وسلامة tenant/branch scope، والتوافق مع Workday، ثم اختبارات الوحدة والثابتة وبناء المشروع.
7. مراجعة التغييرات المتزامنة على فرع التطوير ومقارنة الملفات قبل إنشاء PR رجوعًا إلى فرع التطوير. لا دمج إلى `main` في أي مرحلة من هذه الدورة.
