# نسخة التطوير والنسخة الاحتياطية القابلة للتنزيل

## مصدر النسخة
- المستودع: `teba-labs/teba-saas-demo`
- الفرع: `integration/unified-test-2026-11-19`
- لا تستخدم `main` باعتباره نسخة المعاينة لهذه المرحلة.

## متى تُنتج النسخة؟
يشغّل GitHub Actions سير `Static contract tests` عند كل تحديث على فرع التطوير. ينفذ أولًا:
1. اختبارات العقود الثابتة `node --test tests/static/*.test.mjs`.
2. فحص صياغة ملفات JavaScript وMJS.
3. بعد نجاح الخطوتين فقط، ينشئ ZIP من الملفات المتتبعة في Commit الفرع نفسه، ثم يحسب SHA-256 ويرفعهما كـArtifact.

اسم الـArtifact: `taiba-smart-lab-development-source`. مدة الاحتفاظ المحددة: 30 يومًا.

## تنزيل النسخة من GitHub
1. افتح تبويب Actions في المستودع.
2. افتح أحدث تشغيل ناجح لسير `Static contract tests` على الفرع المذكور.
3. من قسم Artifacts نزّل `taiba-smart-lab-development-source`.
4. فك ضغط ZIP على جهازك، واحتفظ بملف SHA-256 المرفق للتحقق من سلامة النسخة.

## حدود النسخة
- الأرشيف يشمل كل الملفات المتتبعة في Git على Commit التطوير، بما فيها المصدر والاختبارات والوثائق وملفات الإعداد.
- لا يشمل مجلد `.git` أو ملفات محلية غير متتبعة أو أسرار GitHub Actions.
- نجاح الاختبارات الثابتة وفحص الصياغة لا يساوي نجاح اختبارات PostgreSQL أو RLS أو المتصفح.
- لا يعني وجود ZIP أن النسخة نُشرت على Netlify أو أنها متصلة ببيئة Supabase.
- لا تُعدّل أو تُشغّل migrations على قواعد سحابية لمجرد تنزيل النسخة.

## معاينة الواجهة
يجب أن يكون رابط المعاينة منفصلًا عن النسخة الاحتياطية. نشر Netlify يحتاج إعداد أسرار `NETLIFY_AUTH_TOKEN` و`NETLIFY_SITE_ID` في إعدادات المستودع. عند غيابها يتخطى سير المعاينة النشر؛ ولا يجوز وصف ذلك بأنه نشر ناجح.
