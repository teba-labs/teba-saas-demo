- نُفذ database/tests/verify_tenant_isolation.sql كاملًا على TEST. الملف محاط بمعاملة تنتهي بـ ROLLBACK؛ اكتمل التنفيذ دون خطأ SQL.

- استعلام قراءة فقط بعد الاختبار أكد أن عدد السجلات الاصطناعية المتبقية من بادئات الاختبار يساوي صفرًا في auth.users وtenants وbranches وpatients.

- بعد فتح الأرشفة، عُدّل مرشح فروع Dashboard ليعرض allBranches لمالك المعمل ويضع علامة «مؤرشف» على الفرع المتوقف، حتى يظل تاريخ الفرع قابلًا للاختيار والمراجعة. Workday يظل مقتصرًا على الفروع النشطة.

### ضمانات عدم الإضرار
- الاستيراد يضيف السعر العام (branch_id = null) للتحليل النشط الموجود في كتالوج نفس tenant فقط.
- إذا كان هناك سعر عام حالي، يتم تخطيه؛ لا يتم تحديثه أو استبداله.
- أسعار الفروع الحالية لا تُعد سعرًا عامًا ولا يتم تعديلها أو إيقافها.
- القيد الفريد الحالي uq_test_prices_current_base يمنع وجود سعر عام حالي مكرر، وuq_test_prices_current_branch يبقى مستقلًا لأسعار الفروع.
- الكتابة تتم عبر جلسة مالك المعمل وRLS الحالي، مع بقاء audit trigger قائمًا. لم تُضف أو تعدل أي migration أو policy.
- يتم التحقق من جميع الصفوف والأكواد والأسعار والتكرارات قبل أول كتابة. الأكواد غير الموجودة أو غير النشطة توقف العملية قبل الكتابة.
- السعر يقبل صفرًا أو رقمًا غير سالب حتى منزلتين عشريتين؛ التنسيقات الملتبسة تُرفض بدل تخمينها.
- إعادة المحاولة تتخطى السعر الذي أُضيف سابقًا. الفشل الجزئي يظهر لكل كود، وفشل تحديث الكاش المحلي لا يُصنّف السعر المحفوظ سحابيًا على أنه فشل.
- الاستيراد يتطلب الإنترنت، ولا يغيّر أسعار الفروع.

### حدود اختبار البيانات
- مشروع TEST يحتوي حاليًا على تحليل كتالوج واحد غير نشط، وصفر تحاليل نشطة، وسعر حالي واحد؛ لذلك لم يُنفذ استيراد أسعار حي ولم تُكتب أي أسعار تجريبية في قاعدة TEST.
- أضيفت اختبارات unit وstatic للمطابقة، والتكرار، والأسعار العشرية، وعدم استبدال الأسعار، وسلامة سعر الفرع.

## 6. مراجعة إعدادات النظام السبعة

- الهوية وبيانات المعمل: تحميل وحفظ بيانات المعمل مع تحقق من الاسم ورسائل الخطأ.
- الفروع: إنشاء وتعديل وأرشفة وإعادة تفعيل، مع بقاء التاريخ، وتحديث بيانات السياق بعد التغيير.
- الموظفون والصلاحيات: أسماء تشغيلية لكل فرع، تعديل الاسم دون تغيير Auth linkage، إيقاف/إعادة تفعيل، وربط حساب دخول عبر Edge Function.
- بنود المصروفات: إضافة وتعديل الاسم وإيقاف/إعادة تفعيل دون حذف الحركات القديمة.
- إعدادات الطباعة: إعداد عام أو خاص بفرع، JSON validation، وحفظ tenant-scoped.
- البيانات والنسخ: روابط فحص/استيراد Excel ومركز المزامنة والنسخ المحلية؛ لا توجد نسخة Cloud backup ضمن هذا المسار.
- سجل التعديلات: آخر 50 حركة metadata فقط، مع actor/branch labels، دون كشف محتوى النتائج أو before/after.
- أثناء المراجعة ظهر تكرار event listener لقوائم الموظفين وبنود المصروفات؛ كان الضغط الواحد يرسل طلب تحديث مكررًا. أزيل المعالج المكرر، وأضيف اختبار static يضمن وجود معالج delegated واحد لكل قائمة.
- هذا تدقيق ربط كود واختبارات static؛ لم يتم ادعاء اختبار كل زر من متصفح حي.
