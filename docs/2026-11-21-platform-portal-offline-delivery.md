## سجل التنفيذ
- تم التأكد أن فرع التنفيذ وفرع النسخة الاحتياطية موجودان، وأن فرع التنفيذ يبدأ من نفس SHA الرئيسي؛ لم يتم تعديل main.
- تمت مراجعة شاشة TAIBA TECH الحالية، محرر CMS، بوابة المرضى، إعدادات المعمل، قاعدة Offline، وسلسلة migrations.
- أضيف مركز «إدارة موقع المعمل» كواجهة موحدة أولية، مع اختيار المعمل، رابط مباشر لمحرر المحتوى الحالي، معاينة فعلية للبوابة، ومراقبة قراءة فقط لآخر 100 زيارة وحالة نشرها عبر جميع فروع المعمل.
- مراقبة النشر owner-only وتعتمد RLS، وتجلب المرضى والفروع منفصلين مع تقييد tenant_id؛ لا تنفذ نشرًا أو تعديلًا للنتائج.
- أضيف اختبار static contract للمركز الجديد.

## حدود ما لم يكتمل بعد
- لم يتم بعد بناء محرر بصري موثق لإعدادات بوابة المرضى؛ عمود site_settings الحالي لا يحتوي إعدادات portal مستقلة، وlab_settings.settings_json حقل عام دون مفاتيح بوابة موثقة. لن يتم اختراع schema أو الكتابة فوق JSON مجهول.
- لوحة TAIBA TECH تحتاج استكمال إدارة دورة الاشتراك (تاريخ البداية/النهاية، التجديد، المدفوعات، سجل التغييرات، الدعم والاستخدام) وربطها بخدمات خادمية. لا تُعد الأسعار أو الفواتير أو التحصيلات منفذة.
- سياسة Offline 7 أيام لم تُنفذ بعد. محرك Outbox الحالي أساس للمزامنة فقط، وليس سير عمل Offline كاملًا لكل النتائج والاعتماد والنشر. لا يجوز قفل أو حذف العمليات المعلقة لمجرد انتهاء الاشتراك.
- لا يوجد حتى الآن ترخيص Offline موقّع ومتحقق منه من الخادم؛ لا يمكن فرض 7 أيام بأمان اعتمادًا على ساعة المتصفح وحدها.
- لم يتم نشر migrations أو تغيير مشروع Supabase في هذه الخطوة.
- الاختبارات الساكنة لم تُشغّل بعد على GitHub Actions لهذه الإضافة، ولم يتم اختبار المتصفح الحي أو حسابات حقيقية.

## ضوابط الاستكمال
1. عدم تعديل main قبل موافقة المالك.
2. عدم منح مدير المنصة وصولًا لبيانات المرضى الفردية أو النتائج.
3. أي إعدادات بوابة جديدة يجب أن تحفظ القيم الحالية ولا تتلف JSON سابقًا.
4. يجب أن يبقى Outbox محفوظًا حتى بعد انتهاء الاشتراك، وتتم المزامنة الآمنة بعد عودة الاتصال وفق سياسة خادمية.
5. لا يُعلن اكتمال أي جزء إلا بعد اختبارات العقد وRLS والتشغيل الفعلي حيثما أمكن.
